## 已知问题

- **本机台账可能落后于服务器**：本机执行 `更新线上.py` 前必须先 `git pull`，或用服务器版本覆盖 `数据\`，否则会把旧台账推回仓库（11-25 晚发生过一次，已回滚）。
- **不要在两台机器同时启用定时任务**：服务器已是主运行机，本机不要再恢复 DSH 调度。
- 服务器 `dsh` 必须带 `PATH=/opt/node24/bin:$PATH`，否则 `#!/usr/bin/env node` 会落到系统 Node18，静默失败。
- 服务器到 GitHub 的 HTTPS git 通道不通，remote 必须用 `git@github.com:...`（SSH）。
- 会话历史不在仓库里（DSH 会话存本机 `%USERPROFILE%\.dsh`），跨机接续只靠本文件 + 报告 + 台账。
- 仓库公开，`报告\` 与 `数据\` 里的条目必须保持已脱敏。

## 人工接管时怎么起步

1. 读 `README.md` → `规则\采集规则.md` → `规则\来源清单.md`
2. 读 `数据\线索台账.jsonl` 与最近一期 `报告\`，了解已入库与在办情况
3. 本机：`git pull` 后再动数据；服务器：`systemctl start wuhan-leads.service` 手动跑一期，日志在 `/opt/wuhan-leads/logs/`
4. 收尾：`python 工具\生成看板.py` → `python 工具\更新线上.py`（服务器由 `部署/run.sh` 自动完成）
